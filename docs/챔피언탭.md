## 스킨 탭 (2026-08-13 신설·공개)

왼쪽 얼굴 중심 썸네일 세로줄 + 오른쪽 원본 일러스트. 골격은 스킬 탭과 같다.
예전엔 DD 스플래시 격자 + 전체화면 상세보기였고, 그때 쓰던 함수 5개
(`openSkinDetail`·`closeSkinDetail`·`prevSkin`·`nextSkin`·`updateSkinDetail`)는 **지웠다**.
DD 폴백도 같은 레이아웃을 타므로 경로가 하나다.

- **★ 데이터는 CommunityDragon 이다.** `ko_kr/v1/champions/<숫자키>.json` 이 스킨마다
  경로를 직접 알려준다. **173명 전원 확보 / 스킨 2111개 / 경로 빠진 자리 0** (전수 확인).
  - `splashPath` 1280x720 얼굴 중심 (78KB) — 왼쪽 썸네일
  - `uncenteredSplashPath` 1215x717 **원본 일러스트** (185KB) — 오른쪽 큰 그림
  - `tilePath` 380 정사각 (39KB) / `loadScreenPath` 308x560 세로 (53KB) — 아직 안 쓴다
  - 한국어 스킨 이름·**설명글**·희귀도·크로마도 같이 온다. **설명은 2111개 중 312개가 빈칸**이라
    없으면 줄을 통째로 접는다
- **★ CD 경로는 전부 소문자로 바꿔야 한다.** 원문이
  `/lol-game-data/assets/ASSETS/Characters/...` 인데 실제 파일은 소문자다 (`cdAssetUrl`)
- **★ 스킨 번호는 연속이 아니다.** 가렌은 86011 다음이 **86013** 이다 (86012 는 없다).
  그래서 번호를 세서 만들지 말고 CD 가 준 목록을 그대로 쓴다.
  DD 로 `Garen_12.jpg` 를 부르면 403 이 나는 게 이 때문이다
- **썸네일은 `loading="lazy"` 다.** 탭이 `display:none` 인 동안엔 **한 장도 안 받는다**
  (실측: 미스 포츈 24개 중 탭 열기 전 0개 / 연 직후 14개 / 끝까지 스크롤 후 24개).
  스킨 최다는 미스 포츈 24개
- **`.skin-item-img` 와 `.skin-view-frame` 에 `aspect-ratio` 를 못 박았다.**
  이미지가 늦게 오면 높이가 0 이었다 늘어나며 목록이 아래로 밀리고 스크롤 위치가 튄다
- **목록은 자기 스크롤을 갖는다.** 바깥 스크롤에 맡기면 스킨 24개짜리에서
  오른쪽 큰 그림이 화면 밖으로 밀려난다

### 스킨 등급 아이콘 · 가격 (2026-08-13)

목록에는 `(등급 보석) 스킨 이름`, 오른쪽에는 `(보석) 이름 - 1820RP` 로 나간다.

- **등급 보석은 CD 에 이름으로 6종만 있다** — `v1/rarity-gem-icons/` 의
  `epic` / `legendary` / `mythic` / `ultimate` / `exalted` / `transcendent`.
  **`rare.png` 는 404 다.** `kRare`(19개)·`kNoRarity`(832개)는 인게임에서도 보석이 없는
  등급이라 빈칸으로 두는 게 맞다. (같은 폴더의 `1.png`~`11_large.png` 는 번호판인데
  스킨 데이터의 `rarityGemPath`·`regionRarityId` 가 **2146개 전부 null/0** 이라 못 쓴다)

**★★ 가격은 CommunityDragon 에 없다. 롤위키에서 받아 온다.**
CD 스킨 객체 23개 필드에 가격이 없고, `v1/` 아래 60여 개 json 에 store/catalog 도 없다
(`rcp-fe-lol-store` 는 css·png 뿐, `loot.json` 은 TFT 맵용). 스토어 API 는 로그인이 필요하다.
→ 롤위키 **`Module:SkinData/data`** (Lua 표 2.08MB) 를 `build_skin_prices.js` 가 받아
`public/skin_prices.js` (19KB) 를 만든다. **한 번 받으면 되고 런타임 의존은 없다.**

- 위키 표는 들여쓰기가 완전히 일정해서(챔피언 2칸 / 필드 4칸 / 스킨 6칸 / 스킨필드 8칸)
  Lua 를 해석할 필요 없이 그 층만 보면 된다
- **조인 키는 숫자다.** 위키의 챔피언 `id` = DD 숫자키, 스킨 `id` = 스킨 번호.
  CD 스킨 id = `챔피언키 x 1000 + 번호` 라 정확히 맞는다. **이름으로 맞추려 하지 말 것** —
  위키는 영문이고 챔피언명 표기도 다르다(`Nunu & Willump` 등)
- 결과: **RP 1869 / 신화 정수 119 / 가격 없음 123** (합 2111 = CD 스킨 수와 일치).
  가격 없음은 배틀패스·랭크 보상·코드 등 **애초에 파는 물건이 아닌 것들**이다.
  위키에 항목 자체가 없는 건 3개뿐이다 (삼바 애니비아, 펄스 건 리븐, 불멸의 영웅 리븐)

**★ 등급으로 가격을 추측하면 안 된다 (전수 확인).**

| 등급 | 가격 |
|---|---|
| kLegendary | 1820 × 123 — 그런데 **975 가 2개** |
| kEpic | 1350 × 976 — 그런데 **975 가 2개** |
| kUltimate | 3250 × 6 — 그런데 **2775 가 1개** (기동총격여신 미포) |
| kNoRarity | 975 / 520 / 750 / 880 / 790 / 585 / 260 / 390 / 460 / 5000 / 150000 … 제각각 |

- **★ 신화 정수 가격은 `cost` 가 아니라 `distribution` 에 있다.**
  프레스티지 스킨은 `cost="Special"` + `distribution="150 Mythic Essence"` 다.
  100/125/150/200 네 종류가 있고 119자리다
- **★ 기본 스킨의 `cost` 는 스킨값이 아니라 챔피언 가격이다.** 이렐리아·트런들·스웨인
  등의 `880` 이 그것이다. 그대로 찍으면 **"기본 스킨 - 880RP" 라는 없는 상품**이 된다.
  `isBase` 면 가격을 안 붙인다
- 5000(바다사자 우르프)·150000(우르프 워윅)은 오류가 아니라 **라이엇의 농담 가격**이다
- 표기는 콤마 없이 `1820RP` / `150 (신화 정수 아이콘)` 이다.
  **아이콘 경로는 `v1/lolcurrency.json` 이 알려준다** (`lol_mythic_essence` →
  `assets/currencies/images/mythic-essence-icon.svg`). 15x18 짜리 svg 고 그라데이션이
  파일 안에 있어서 어두운 배경에서 그대로 보인다. RP·블루 에센스 아이콘도 같은 파일에 있다.
  `skinPriceHtml()` 이 **HTML 을 돌려주므로 이스케이프하면 안 된다** — 값은 우리가 만든
  표의 숫자라 위험이 없다

### 크로마 (2026-08-13)

설명 아래에 색점을 한 줄로 깔고, 누르면 큰 칸이 그 크로마 **3D 모델 렌더**로 바뀐다.
다시 누르면 일러스트로 돌아온다.

- **★ 크로마도 같은 `champions/<키>.json` 안에 있다 — 추가 요청이 0이다.**
  **1037개 스킨에 크로마 6972개** (전체 스킨 2111개 중 절반). 한 스킨 최다는
  **2018 월드 챔피언십 카직스 25개**이고 20개를 넘는 건 그 하나뿐이다
- **`colors`(1~2색)가 6972개 전부에 있다 — 누락 0.** 그래서 **색점은 이미지 없이** 그린다.
  두 색이면 `linear-gradient(135deg, …)` 로 반씩 나눈다
- **★ 그림(`chromaPath`)은 270x303 투명 배경 3D 모델 렌더다.** 장당 82KB 라
  카직스면 2MB — **눌렀을 때만 받는다.** 일러스트(가로)와 세로 비율이 달라서
  `object-fit` 을 `cover` → `contain` 으로 바꿔야 한다 (`.is-chroma`). 안 그러면 얼굴이 잘린다
- **★ 뒤에 원래 일러스트를 흐리게 깐다 (`.skin-view-bg`).** 세로 인물이라 칸의 **53%만
  차고 284px 가 비는데**, 그 자리를 메운다. **이미 받아 둔 그림이라 추가 요청이 0이다.**
  - **흐림을 칸에 걸면 안 된다** — 자식인 인물 그림까지 흐려진다. 배경만 따로 깐 층에 준다
  - 칸에 `position: relative` 가 있어야 하고, 배경에 `transform: scale(1.1)` 이 필요하다 —
    `blur` 가 가장자리를 투명하게 갉아 칸 테두리에 띠가 생긴다
  - 스킨을 바꿀 때도 배경을 지워야 한다 (`selectSkin` 과 `selectChroma` 양쪽에서 지운다)
  - **이게 "스킨 인게임 모습" 에 제일 가까운 공식 이미지다.** 위 "프로필 아이콘·모스트" 절에서
    "렌더된 이미지는 없다" 고 적었는데, **크로마가 있는 스킨(1037개)에는 있다**
- 한국어 크로마 이름(`도자기 럭스 (장미석)`)과 설명 1521개가 같이 온다

**★★ 점은 그림 오른쪽 세로줄이다 (`.skin-stage`, 2026-08-13).**
그림 아래 가로줄이던 걸 옮겼다. 세 가지가 한 번에 풀린다 —
**① 세로 예산 40px 회복**(그래서 여유값이 320 → 300 이 됐고 창 900px 에서 그림이
602 → 635 로 커졌다) **② 점이 바꾸는 대상 바로 옆에 온다**(전엔 121px 아래였다)
**③ 그림이 자연히 왼쪽으로 치우쳐** 오른쪽에 점이 놓일 자리가 생긴다.

- **★ `--skin-frame-h` 를 `.skin-stage` 에 두고 그림 `height` 와 점칸 `max-height` 가
  같이 쓴다.** 둘이 어긋나면 접히는 기준이 없어져 **카직스(25개)가 한 칸으로 쭉 뻗어
  113px 넘쳤다** (실제로 그렇게 났다). 지금은 2칸으로 접힌다
- **★ `align-items: stretch` 여야 한다.** `flex-start` 면 점칸이 내용 높이대로 늘어나
  wrap 이 판단할 기준을 못 얻는다
- 점칸이 2칸이 되면 그림이 그만큼 좁아진다 (`.skin-view-frame` 이 flex 항목이라
  알아서 줄어든다). 25개짜리는 카직스 하나뿐이고 그다음이 11개라 나머지 1036개는 1칸이다
- **크로마 이름은 이름 줄 뒤에 ` · 장미석` 으로 붙인다** — 줄을 새로 안 만들어 높이를 안 먹는다.
  **`"… (색이름)"` 꼴이 6972개 중 6971개(100.0%)** 라 괄호 안만 뽑으면 스킨 이름이 안 겹친다
  (유일한 예외는 `2017 월드 챔피언십 애쉬 크로마`)
- **폰에서는 다시 그림 아래 가로줄로 되돌린다.** 세로 화면에서 오른쪽에 세로줄을 세우면
  안 그래도 좁은 그림 폭을 더 뺏긴다

아래는 점이 그림 **아래**에 있던 시절의 기록이다.

**★★ 크로마 줄은 한 줄이어야 한다 — 높이 예산이 빠듯하다.**
처음엔 이름 줄 + 점 줄 2단(59px)으로 만들었는데 설명이 긴 스킨에서 **23px 넘쳐 스크롤이
생겼다** (선지자 야스오 261자+크로마 8개 / 겨울의 축복 헤카림 / 하이 눈 이블린이
**전부 정확히 23px**였다). 한 줄로 합쳐 32px 로 줄여도 **12px 이 모자랐다.**

- **★ 그림 폭과 설명 줄간격은 한 예산을 나눠 쓴다.** 남은 12px 은 그림(600px)을 줄이는
  대신 **설명 줄간격을 1.7 → 1.5** 로 조여서 벌었다 (1.6 은 5px 부족, 1.55 는 2px 밖에
  안 남는다). **하나를 키우면 다른 하나를 조여야 한다**
- **★ 폭 스윕은 단조롭지 않다.** 야스오에서 `580px 은 23px 넘치는데 590px 은 6px` 이었다 —
  폭이 넓어지면 줄 수가 줄어드는 순간이 있어서 뒤집힌다. **한 점만 재고 판단하지 말 것**
- **★ `row.style.display` 에 `block` 을 넣으면 안 된다.** 인라인 style 이 CSS 의
  `display:flex` 를 이겨서 라벨과 점이 위아래로 갈라진다.
  **챔피언 목록에서 겪은 것과 같은 함정이다** (위 "★ 챔피언 목록 항목을 숨길 땐" 항목)
- **라벨은 폭을 못 박는다(150px, 폰 92px).** 안 그러면 크로마를 고를 때마다 이름 길이가
  바뀌어 **점들이 좌우로 밀린다** — 다음 점을 누르려는데 자리가 옮겨진다.
  같은 이유로 줄 자체에도 `width:100%` 를 줘서 내용에 따라 안 흔들리게 했다

**★★★ 오른쪽 일러스트는 폭이 아니라 높이로 정한다 — `min(378px, 75vh - 300px)` (2026-08-13).**
`640px` 고정으로 뒀다가 **"멜은 스크롤 안 생기는데?" 라는 지적에 전제가 드러났다** —
내 측정이 전부 **창 높이 900px** 한 점에서만 이뤄졌던 것이다. 칸 높이가
`75vh - 120px` 로 따라 움직여서(vh 768/800/900/1000 → 456/480/555/630, 차이가 늘 120px),
창이 조금만 낮아도 결과가 뒤집힌다. **고정 폭으로 잰 640px 의 실제 성적:**

| 창 높이 | 500px | 600px | 640px 고정 | **지금(높이 기준)** |
|---|---|---|---|---|
| 768 (노트북) | 36% | 75% | **82%** | **4%** |
| 800 | 13% | 50% | 73% | 1% |
| 860 | 0% | 21% | 39% | 0% |
| 900 | 0% | 0% | 1% | 0% |
| 1000 이상 | 0% | 0% | 0% | 0% |

- **★ 고정 폭으로는 답이 없다.** 노트북(768px)에서는 500px 로 줄여도 36% 가 스크롤한다.
  높이를 창에 맞춰 줄이는 것만이 근본 해결이다
- `300px` = 칸 밖 여백 120 + 글 몫 180(이름 42 + 설명). **크로마 점을 오른쪽으로 옮기면서 320 → 300 이 됐다** (세로 예산 40px 회복).
  여유값 실측(창 768/800/900): `280 → 16%/8%/0%` · **`300 → 4%/1%/0%`** · `320 → 1%/0%/0%`.
  **320 은 창 900px 에서 그림이 602 로 작아진다** — 짧은 창을 더 챙기고 싶으면 320 으로 올린다
- **1000px 이상 창에서는 천장(378px, 곧 641x378)에 걸려 아무 영향이 없다** —
  큰 화면 사용자에게는 640px 고정과 똑같이 보인다
- **★ 폰에서는 이 계산을 되돌려야 한다** (`height:auto; width:100%`).
  폰은 칸이 `75vh` 가 아니라 `auto` 라 `75vh - 300px` 이 칸 높이와 무관하고,
  그 높이로 폭을 역산하면 화면(338px)보다 넓어져 비율이 깨진다
- **★★ 교훈: 높이가 `vh` 로 정해지는 칸 안에서 크기를 맞출 땐 창 높이를 여러 개 재라.**
  한 점(900px)에서만 재고 "12개만 스크롤한다" 고 결론지었는데, 실제로는 그 점이
  **절벽 바로 위**였다 (900 → 1%, 860 → 39%)

아래는 폭만 놓고 재던 시절의 기록이다. **분포로 정한다는 원칙은 그대로 유효하다.**

**★★ 크기는 "최악 한 개" 가 아니라 분포로 정할 것 (2026-08-13).**
처음엔 제일 긴 설명(**멜 293자, 2111개 중 유일한 최장**) 하나를 기준으로 500px 까지 줄였다.
