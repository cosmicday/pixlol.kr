## 신화급 상점 (2026-08-16 신설)

윈도우 로컬 수집기(별도 프로젝트 `C:\Users\admin\Desktop\mythic-collector`)가 롤 클라
화면을 읽어 서버로 보낸다. **명세는 그쪽의 `SERVER_SPEC.md` 가 정본이고 받는 쪽만
여기 있다.** 첫 화면의 "오늘의 신화 상점" 위젯이 읽는다 (예전엔 하드코딩 4개였다).

- 서버: `server.js` 의 `mythicShopSchema` + `POST /api/mythic-shop` + GET 3종
- 화면: `app.js` 의 `loadMythicShop()` / `index.html` 의 `#mythic-items` / `.mythic-*` CSS

**★ 정적 파일이 아니라 DB 인 이유**: Railway 파일시스템이 배포마다 날아가서 서버가 파일을
못 만든다. 정적 파일로 가면 수집할 때마다 사람이 git push 를 해야 한다.
**TTL 이 없다 — 영구 기록이다.** 하루 4건 x 200B 라 1년에 300KB 다.

- **★★ `date` 는 UTC 기준이다.** 로테이션이 00:00 UTC(한국 09:00) 갱신이라 그게 곧
  로테이션 ID 다. **한국시간 오전 9시 전에는 한국 날짜와 하루 어긋난다** — 화면에
  "8월 16일 로테이션" 이라고 날짜를 같이 적는 이유다. `kstDay()` 와 헷갈리지 말 것
- **★★ `items: null` 을 반드시 구분해서 보여줄 것.** 서버가 404 가 아니라
  `200 + items:null` 로 주는 이유도 이것이다 — 404 면 화면에서 서버 오류와 구분이 안 된다.
  **이건 예외가 아니라 일상이다** — 수집기가 라이엇 약관·뱅가드 때문에 클릭 자동화를
  포기하고 **사용자가 상점 화면을 열고 단축키를 눌러야** 수집되는 구조라,
  안 누른 날은 데이터가 아예 없다. **어제 것이 오늘 것처럼 보이면 안 된다**

**★★ Cloudflare 가 기본 User-Agent 를 막는다 — `403 error code: 1010` (2026-08-16).**
수집기 첫 전송이 이걸로 막혔다. `User-Agent` 를 안 붙여서 `Python-urllib/3.9` 로 나갔고
Cloudflare 가 그걸 보고 잘랐다. **Express 까지 오지도 않아서 서버 로그에 아무것도 안 남는다** —
서버가 고장 난 것처럼 보이는데 우리 쪽엔 단서가 0이다.

- 수집기는 `mythic-collector/0.1 (+https://pixlol.kr)` 로 붙여서 바로 통과했다
- **Cloudflare 설정은 안 건드려도 된다.** 다만 **브라우저가 아닌 클라이언트를 새로 붙일 때마다
  같은 데서 막힌다** — curl·python·node 스크립트 전부 해당한다. 제대로 된 UA 를 붙일 것
- 우리 쪽 401 의 `detail` 로도 이건 구분이 안 된다 (요청 자체가 서버에 안 온다).
  **403 이면 Cloudflare, 401 이면 우리 서버**로 갈라서 보면 된다
- **★ 이미지 URL 은 수집기가 만들어 보낸다. 서버·프론트가 만들지 말 것.**
  아이콘은 `v1/profile-icons/{id}.jpg` 로 유추가 되지만 **감정표현은 경로가 제각각이다**
  (`assets/loadouts/summoneremotes/tft/grindrewards/4264_untamable_inventory.png`).
  수집기가 CD 카탈로그 16,764개를 들고 있어서 거기서 뽑아 준다. `image` 가 없는 경우도 있다

### 검증 — 수집기를 믿지 않는다

화면을 잘못 읽을 수도 있고 토큰이 새면 아무나 보낼 수 있다. **틀린 값이 조용히 들어가는 게
이 기능에서 가장 나쁜 결과**라 서버에서 다시 본다 (`validateMythicBody`).

- `date` 형식·미래 금지 / `items` 1~12개 / `name` 1~200자 / `type` icon|emote /
  `price` 5|25 / **타입↔가격 일치**(아이콘 5, 감정표현 25 고정)
- **★ `image` 는 `https://raw.communitydragon.org/` 로 시작해야 한다.** 이 값이 그대로
  `<img src>` 에 들어가므로, 토큰이 샜을 때 임의의 URL 을 심는 걸 막는다
- 토큰은 `X-Collector-Token` 헤더 ↔ `process.env.COLLECTOR_TOKEN`.
  **양쪽을 sha256 으로 눌러 길이를 맞춘 뒤 `timingSafeEqual`** 로 본다
  (길이가 다르면 그 함수가 예외를 던진다)
- **★★ 401 이 나면 `detail` 을 볼 것 — 원인이 셋인데 고칠 곳이 다 다르다:**

  | `detail` | 뜻 | 고칠 곳 |
  |---|---|---|
  | `server_token_missing` | 서버에 `COLLECTOR_TOKEN` 이 없다 | **Railway 환경변수** |
  | `header_missing` | 헤더가 안 왔다 (프록시가 지웠을 수도) | 수집기 설정 · 프록시 |
  | `token_mismatch` | 값이 다르다 | 수집기의 `upload_token` |

  처음엔 셋을 전부 `401` 로만 돌려줬더니 **프로덕션에서 401 이 났을 때 뭘 고쳐야 하는지
  알 수가 없었다** (실제로 2026-08-16에 겪었고 `server_token_missing` 이었다 —
  Railway 에 값을 넣고 Deploy 를 눌러야 프로세스에 들어간다).
  토큰 값은 안 흘리고, 맞았는지 여부는 어차피 201/401 로 드러나므로 새는 정보가 없다

### ★★ 같은 날짜 중복은 조용히 덮어쓰지 않는다

같은 날짜에 다른 내용이 온다는 건 둘 중 하나가 틀렸다는 뜻이라 사람이 봐야 한다.

| 상황 | 응답 |
|---|---|
| 그 날짜 문서 없음 | `201 {ok:true, created:true}` |
| 있고 **내용 같음** | `200 {ok:true, created:false}` |
| 있고 **내용 다름** | **`409` + `existing`·`incoming` 둘 다 담아서** |
| `?force=1` | 덮어쓰고 `200 {overwritten:true}` |

- **★ 같은지는 `name`/`type`/`price` 로만 본다.** `score` 와 `collected_at` 은 같은 화면을
  두 번 읽어도 달라져서 뺀다 (`mythicFingerprint`)
- 수집기는 409 를 받으면 재시도하지 않고 사람에게 알린다. 대기열에도 안 쌓는다

### ★★ `date` 의 unique 인덱스가 스키마 선언만으로는 안 만들어졌다

스키마에 `unique: true` 를 써 놨는데 **실제 인덱스는 `_id_` 와 복합 인덱스뿐이었다**
(2026-08-16 실측). `ensureStatIndexes()` 의 `want` 에 따로 적어서 만든다.
**이게 없으면 같은 날짜가 동시에 두 번 들어올 때 문서가 둘 생기고** POST 의 11000 처리도
영영 안 탄다. 넣고 나서 서로 다른 내용을 동시에 쏴 보니 **하나는 201, 하나는 409 고
문서는 1건**인 것을 확인했다. (위 "스키마에 인덱스를 적어도 안 만들어진다" 절과 같은 함정)

### 시험할 때

- 로컬 `.env` 에 `COLLECTOR_TOKEN` 이 이미 있다. **로컬 서버는 프로덕션 DB 를 쓰므로
  시험용 문서는 과거 날짜(`2020-01-01` 등)로 넣고 끝나면 반드시 지울 것.**
  오늘 날짜로 넣고 안 지우면 **실서비스 첫 화면에 가짜가 뜬다**
- 검증 규칙을 한 줄씩 누르려면 30번 넘게 쏴야 해서 레이트리밋에 막힌다.
  `COLLECTOR_RATE_MAX=1000` 으로 띄우면 풀린다. **프로덕션 환경변수에는 넣지 말 것**
  (기본 10회/분). `POST` 도 `/api/` 공용 리밋(30회/분)을 같이 먹으니 GET 검사 전에 쉬어야 한다

### 화면 — 신화상점 탭 (2026-08-17 신설)

메뉴 순서는 `전적검색 · 랭킹 · 통계 · 챔피언 · 도감 · 신화상점` 이다. 소메뉴 4개는
**인게임 상점 구획을 그대로 따랐다** — `추천 / 격주 / 주간 / 일일`.
`app.js` 의 `MYTHIC_TABS` · `showMythicShop()` · `renderMythicSection()` /
`style.css` 의 `.mshop-*` / 주소는 `/mythic/<탭키>`(`featured|biweekly|weekly|daily`).

- **★ 지금 데이터가 있는 건 일일 하나뿐이고, 나머지 셋은 보내와도 서버가 거절한다.**
  `validateMythicBody` 가 `type` 을 `icon|emote`, `price` 를 `5|25` 로 못 박고 있어서
  스킨·크로마·와드(신화 정수 가격 제각각)가 오면 **400** 이다. 게다가 `date` 가 unique 라
  한 날짜에 문서가 하나뿐이라 네 구획을 담으려면 `section` 같은 칸이 필요하다.
  → **★★ 2026-08-17에 서버를 고쳐서 이 문단은 옛말이 됐다. 아래 "구획 4개" 절을 볼 것.**
- **★ 화면은 네 탭 모두 실제 API 를 부른다** — 일일은 `/today`, 나머지 셋은 `/section/<키>`.
  **수집기가 보내기 시작하면 코드를 한 줄도 안 고쳐도 켜진다.** 아직 안 들어온 구획은
  `items: null` 이라 "아직 수집 전" 안내가 나간다
- **★★ 헤더는 "언제 읽었나" 가 아니라 "언제까지 파는지" 를 말한다 (2026-08-17 개편).**
  예전엔 `8월 17일 기준 · 오늘` + `수집 2026. 8. 17. 오후 2:23:11` 이었는데, **둘 다
  우리 사정이지 사용자가 궁금한 게 아니다.** 지금은 제목 옆이 **다음 초기화까지 남은 시간**,
  오른쪽 끝이 **판매 기간**(`2026. 08. 17. 09:00 - 2026. 08. 18. 09:00`)이다
- **★★ 날짜를 박아 두지 않는다 — 기준 시각 하나 + 주기로 계산한다** (`MYTHIC_RESET`).
  박아 두면 다음 로테이션부터 조용히 틀린다. 초기화는 **전부 한국시간 09:00 = 00:00 UTC** 라
  UTC 자정을 기준으로 세면 된다:

  | 구획 | 주기 | 기준(anchor) | 툴팁 |
  |---|---|---|---|
  | 일일 | 1일 | 아무 날 | `매일 09시 초기화` |
  | 주간 | 7일 | `2026-08-20`(목) | `매주 목요일 09시 초기화` |
  | 격주 | 14일 | `2026-08-19`(수) | `격주 수요일 09시 초기화` |
  | 추천 | **없음** | — | 로테이션이 아니라 **상품마다 기한이 다르다** |

  `Math.floor((now - anchor) / step)` 이라 기준보다 과거여도 맞게 나온다.
  실측 대조: 주간 `08.13 09:00 - 08.20 09:00` · 격주 `08.05 09:00 - 08.19 09:00`
- **★ 시계는 하나다 (`updateShopTimer`).** 첫 화면 위젯 · 구획 헤더 · 추천 상품 딱지가
  모두 `.js-shop-timer` 고, **각자 `data-until` 로 목표 시각을 들고 있다.**
  없으면 일일 초기화로 본다 — 첫 화면 위젯이 그 경우라 예전 동작 그대로다
- **★★ 추천 상품 기한은 손으로 적어 뒀다 (`MYTHIC_ITEM_END`).** 수집기가 그 값을 안 준다.
  **모르는 상품은 딱지를 안 붙인다** — 틀린 기한을 붙이는 것보다 낫다. 로테이션이 바뀌면
  표를 갈아야 하고, 안 갈면 **딱지가 사라질 뿐 틀린 값이 나가지는 않는다.**
  수집기에 `ends_at` 을 실어 달라고 요청해 뒀다 (`SERVER_STATUS.md` ③번)
- **★ 상품 딱지 툴팁만 `title`(네이티브)이다.** 카드가 `overflow: hidden` 이라
  CSS 툴팁(`[data-tooltip]::after`)이 카드 밖으로 못 나가고 잘린다. 헤더 쪽은 카드 밖이라 CSS 툴팁을 쓴다
- **기본 탭이 `추천`(인게임 순서)이라 들어오자마자 "아직 수집 전" 이 보이는 게 정상이다.**
  그래서 안내에 이유를 적고 **일일로 가는 버튼**을 둔다 — 빈 칸만 있으면 고장으로 읽힌다
- **★ 카드는 첫 화면 위젯과 같은 `mythicCardHtml()` 하나를 쓴다.** 두 벌로 두면 같은 상품이
  화면마다 다르게 보인다. `image` 는 서버가 `raw.communitydragon.org` 로 시작하는지 이미
  검증한 값이라 그대로 `src` 에 넣고, 이름만 이스케이프한다
- **★★ 카드 줄은 격자가 아니라 flex 다 — 격자로는 두 조건을 동시에 못 맞춘다.**
  ① 일일 4개는 한 줄을 꽉 채워야 하고 ② 상품이 2개뿐인 구획에서 카드가 600px 로 벌어지면 안 된다.
  `grid + auto-fill` 은 ①이 깨지고(빈 칸을 6개 만들어 왼쪽으로 몰린다),
  `grid + auto-fit + minmax(160px, 260px)` 로 ②를 잡으려니 **①이 또 깨졌다** —
  **auto-fit 은 칸 수를 최소폭이 아니라 최대폭으로 센다**(`floor(1035/275)=3`)
  라서 일일 4개가 **3+1 로 갈렸다**. `flex: 1 1 160px` + `max-width: 300px` 면 둘 다 된다.
  실측(창 1400): 4개 → 1줄 253px씩 / 2개 → 300px씩 / 1개 → 300px. 폰 390px 은 2칸 165px씩
- **★ 카운트다운은 `.js-shop-timer` 를 전부 훑는다.** 예전엔 `getElementById('shop-timer')`
  하나였는데, 그 자리가 없으면 **매초 예외가 난다.** 지금은 첫 화면 위젯과 탭 두 군데에 뜬다
- **★★ 메뉴가 6개가 되면서 폰 헤더가 깨졌다 (2026-08-17 실측).** 390px 에서 줄이 넘어간 게
  아니라 **낱말 중간에서 쪼개졌다** — `전적검 / 색`, `신화상 / 점`. 항목 높이가
  **17px → 34px** 로 드러난다. 고친 것 세 가지: `white-space: nowrap` +
  `gap 12 → 8` · `글자 13 → 12px`(이걸로 **390px 에서 한 줄에 들어간다**) +
  좁은 폰용 `overflow-x: auto`(스크롤바는 숨긴다).
  실측: 430/390 은 넘침 0, **360px 에서만 9px 밀린다**(가로 스크롤로 처리).
  **메뉴를 하나 더 늘리면 여기부터 다시 잴 것 — 430px 기준 여유가 거의 없다**
- 일일 탭은 **오늘 것만** 보여준다. 기간 조회(`/api/mythic-shop?limit=`)는 API 만 있고
  화면은 아직 없다 (아래 "남은 일" 23번)

### 구획 4개 — 서버 (2026-08-17)

**`section` 칸 하나를 더했다.** 값은 `featured / biweekly / weekly / daily` 이고
**안 보내면 `daily`** 다 — 구획이 생기기 전 수집기가 그대로 동작해야 하기 때문이다.

- **★★ unique 가 `date` 단독에서 `date + section` 으로 바뀌었다.** 안 바꾸면 같은 날짜의
  **두 번째 구획이 11000 으로 막힌다.** 옛 `date_1` 은 `ensureStatIndexes()` 의 새 `legacy`
  목록이 지운다 — **새 인덱스를 만들기 전에 지워야 한다**(순서가 뒤바뀌면 위 이유로 막힌다)
- **★ 기존 문서에 `section` 을 메우는 것도 인덱스보다 먼저다.** 빠진 필드는 인덱스에서
  `null` 로 잡혀서, 같은 날짜에 `section:'daily'` 가 새로 들어오면 **막히지 않고 문서가 둘 생긴다.**
  `ensureStatIndexes()` 가 시작할 때마다 `{section: {$exists: false}}` 를 `daily` 로 메운다
  (실측으로 2건 + 옛 서버가 넣은 1건이 메워졌다)
- **★★ 배포 순서**: 새 서버가 뜨기 전에 옛 서버가 넣는 문서는 `section` 이 없다.
  옛 서버는 `findOne({date})` 로 찾으므로 **중복을 만들지는 않고**, 새 서버가 뜰 때 메워진다.
  즉 **인덱스를 먼저 갈아 끼워도 안전하지만, 배포는 되도록 붙여서 할 것**

**검증은 구획마다 다르다** (`validateMythicBody`):

| | 일일 | 나머지 셋 |
|---|---|---|
| `type` | **`icon` / `emote` 만** (예전 그대로) | `icon` `emote` `skin` `chroma` `ward` `border` `bundle` `other` |
| `price` | **5 / 25 고정 + 타입과 짝까지 본다** | 1~1000 정수 (`MYTHIC_PRICE_MAX`) |
| 개수 | 1~12 | 1~30 |

- **★ 일일 규칙은 일부러 안 풀었다.** 그 짝 검사가 지금까지 화면 오독을 잡아 왔고,
  일일 구획에 스킨이 뜨는 일은 없다
- **★ 가격 상한 1000 은 "RP 가격을 잘못 읽어 오는 것"(1350 같은 값)을 잡으려고 둔 것이다.**
  프레스티지 125 · 신화 스킨 150 · 크로마 40 근처라 넉넉하다. 정상인데 막히면 여기부터 볼 것
- **★★ 모르는 타입은 `other` 로 보내면 통과한다.** 막아서 그날 데이터를 통째로 잃는 것보다
  받아 두는 게 낫다 — **수집이 반자동이라 한 번 거절당하면 사람이 상점을 다시 열어야 한다.**
  대신 서버가 `[Mythic] <날짜>/<구획> type=other N건: <이름들>` 로 경고를 찍는다.
  쌓이면 `MYTHIC_TYPES` 에 진짜 이름을 더한다
- **주간·격주는 며칠 동안 내용이 같으므로 날짜가 다르면 충돌이 아니다** — 같은 내용이
  날짜별로 하나씩 쌓인다 (한 건 200B 라 그대로 둔다). 409 는 **같은 날짜·같은 구획**에
  다른 내용이 올 때만이다

**엔드포인트** — GET 이 하나 늘었다:

| | |
|---|---|
| `GET /today` | **일일만** 본다. `section: 'daily'` 를 안 걸면 같은 날짜의 주간 문서가 걸려 **첫 화면 위젯에 스킨이 뜬다** |
| `GET /section/:section` | **★ "오늘 것" 이 아니라 "마지막으로 수집한 것"** 이다. 주간·격주는 며칠씩 그대로라 오늘 날짜로 찾으면 늘 빈손이 된다. `ageDays`·`stale` 을 같이 준다 |
| `GET /?section=` | 기간 조회에 구획 필터 추가 |
| `GET /history/:catalogId` | `entries: [{date, section}]` 추가. `dates` 는 그대로 뒀다 |

- **★ `stale` 기준은 구획 주기다** (`MYTHIC_SECTION_PERIOD`) — 일일 0(오늘이 아니면 곧바로) /
  주간 7 / 격주·추천 14. **"어제 것을 오늘 것처럼 보여주지 않는다" 는 원칙을 구획별로
  옮긴 것**이고, 그래서 낡은 데이터도 지우지 않고 **띠를 붙여 보여준다**
- **★ `/section/:section` 은 `/api/mythic-shop` 보다 먼저 선언해야 한다** (history 와 같은 이유)
