# 방송 탭 — 롤 생방송 목록 (2026-09-17)

`/broadcast`. SOOP · 치지직 · 유튜브에서 **리그 오브 레전드 생방송**을 모아 시청자 순으로 보여준다.
카드를 누르면 그 플랫폼 방송이 새 탭으로 열린다.

| 자리 | 무엇 |
|---|---|
| `server.js` 「방송」 절 | 수집 3개 + `GET /api/broadcast` |
| `server.js` `ytChannelSchema` | 유튜브 자동 명단 (`ytchannels`) |
| `broadcast_channels.js` (루트, git 에 있음) | 유튜브 손 명단 — `include` / `exclude` |
| `public/app.js` `showBroadcast()` · `renderBroadcast()` | 화면 |
| `public/style.css` 「방송」 절 | `.bc-*` 카드 격자. 칩·안내 줄·더 보기는 e스포츠 것(`.es-*`)을 그대로 쓴다 |

## 키 (`.env` · Railway Variables 둘 다)

```
SOOP_CLIENT_ID=        # SOOP Developers. 사용 범위: 「방송 리스트」「카테고리 리스트」 둘만 (둘 다 Public)
SOOP_CLIENT_SECRET=    # 지금 코드는 안 쓴다 (목록 조회는 client_id 만 필요)
CHZZK_CLIENT_ID=       # 치지직 개발자센터. scope 는 하나도 안 골랐다 — 라이브 목록은 Client 인증이라 scope 가 필요 없다
CHZZK_CLIENT_SECRET=
YOUTUBE_API_KEY=       # Google Cloud 프로젝트 DOGU-GG. API 제한 = YouTube Data API v3 만. 결제 계정 없음(무료)
```

- **키가 없는 플랫폼은 조용히 빠진다** (칩도 안 그린다). 로컬에서 키 없이 띄워도 나머지는 돈다
- 앱 이름: SOOP 「도구지지」 · 치지직 `dogugg`(한글 불가) · 구글 `DOGU-GG`. **플랫폼 이름(치지직·네이버·SOOP)을 넣으면 거절될 수 있다**
- SOOP 은 문서엔 「제휴 확정 뒤 키 발급(영업일 10일)」이라 적혀 있지만 **실제로는 바로 나왔고 바로 호출됐다**

## 수집 — **요청이 올 때만** 받는다

잡(setInterval)이 아니다. `/api/broadcast` 가 오면 플랫폼마다 「받아 둔 게 주기보다 오래됐나」를 보고,
오래됐으면 **받아 둔 걸 바로 주고 뒤에서 새로 받는다** (처음 한 번만 기다린다, 실측 ~1.1초).
보는 사람이 없으면 바깥 호출이 0 이고, `READONLY_JOBS` 와 무관하게 로컬에서도 화면이 뜬다.

| 플랫폼 | 주기 | 한 번에 하는 일 |
|---|---|---|
| SOOP | 90초 | `GET openapi.sooplive.co.kr/broad/list?select_key=cate&select_value=00040019&order_type=view_cnt&page_no=N` — 60개씩, 덜 차면 끝 (실측 2페이지) |
| 치지직 | 90초 | `GET openapi.chzzk.naver.com/open/v1/lives?size=20&next=…` 를 **시청자 1명 이하가 나올 때까지** (최대 100페이지, 실측 65페이지 · 1.4초) |
| 유튜브 | 12분 | 명단 채널마다 업로드 목록 앞 3개 → 그 영상들의 라이브 여부·시청자 수 |
| 유튜브 새 채널 찾기 | 2시간 | `search` `q=롤` 한 번 (100유닛) |

- 실패하면 1분 동안 다시 안 부른다. 유튜브 할당량이 바닥나면(`quotaExceeded`) **한 시간** 쉰다
- 받아 둔 게 있는데 실패 중이거나 주기의 3배를 넘기면 `platforms.<p>.stale` → 화면에 안내 줄
- **방송 목록은 메모리에만 있다.** DB 에 쓰는 건 유튜브 채널 명단(`ytchannels`)뿐이고 채널당 ~200B 다

### 응답 모양

```js
{ ok: true,
  items: [{ p: 'soop'|'chzzk'|'youtube', id, title, name, viewers /* null = 비공개 */, thumb, avatar, url, start /* ms */ }],
  platforms: { soop: { at, count, stale, error /* null · 'nokey' · 'quota' · 'error' */ }, … },
  ttl: { soop: 90000, … } }
```

실측 크기 ~70KB (180개). 서버는 `(분, 플랫폼별 at·error)` 가 바뀔 때만 JSON 문자열을 다시 만든다.

## 플랫폼별 사실 (2026-09-17 실측)

### SOOP
- **GET 만 된다** — POST 는 405
- 롤 카테고리 = **`00040019`** (`GET /broad/category/list?client_id=…&locale=ko_KR`)
- `total_view_cnt` 는 이름과 달리 **현재 시청자로 보인다** (오전 1위가 698명). ★ 저녁에 SOOP 화면 숫자와 한 번 대조할 것
- 썸네일·프로필 주소가 `//` 로 시작한다 → `https:` 를 붙인다
- 방송 주소 `https://play.sooplive.co.kr/<user_id>/<broad_no>` (301 로 이어진다)
- `is_password === '1'` · `broad_grade >= 19` 는 뺀다 (사용자 결정)

### 치지직
- **카테고리 조건이 없다** — 전체를 시청자 순으로 넘기며 `liveCategory === 'League_of_Legends'` 로 거른다.
  「에이펙스 레전드」·「레전드 오브 바둑」 같은 게 안 섞여서 검색어보다 정확하다
- 응답은 `content.data` / `content.page.next`. 헤더 `Client-Id` · `Client-Secret`
- 썸네일 주소에 **`{type}` 자리표시**가 들어 있다 → `480` 으로 바꾼다
- `adult: true` 는 뺀다
- 방송 주소 `https://chzzk.naver.com/live/<channelId>`

### 유튜브 — 제일 까다롭다

**API 에 「게임 = 리그 오브 레전드」 조건이 없다.** 그래서 채널 명단을 두고 그 채널들만 확인한다.

- **명단 확인 = `playlistItems`(업로드 목록 `UU` + 채널ID 뒤 22자, 1유닛) → `videos`(50개당 1유닛)**.
  실측: 방송 중인 48채널 중 **47채널이 업로드 목록 앞 5개 안에 라이브가 있었다** (빠진 하나는 몇 주째 켜 둔 24시간 재방송)
- **안 되는 길 둘** — 다시 재 보지 말 것
  - 채널 RSS(`/feeds/videos.xml?channel_id=`) — **50개 중 49개가 404·500**
  - `/channel/<ID>/live` 페이지 — 방송 여부는 나오지만 **한 장 1.2MB**. 비공식이기도 하다
- **`search` 에 `order=viewCount` 를 주면 결과가 15개로 줄어든다** (안 주면 50개 + 다음 페이지). 그래서 안 주고 우리가 정렬한다
- 시청자 수를 숨긴 방송은 `concurrentViewers` 가 없다 → `viewers: null` → 맨 뒤, 화면엔 「비공개」
- 한 채널이 동시에 여러 개 송출하면 하나만 쓴다

**할당량 (하루 10,000 유닛, 결제 없음 — 넘기면 그날 막힐 뿐 청구되지 않는다)**

| 무엇 | 1회 | 하루 |
|---|---|---|
| 명단 확인 (60채널) | 60 + 약 4 | 12분마다 120회 → **~7,700** |
| 새 채널 찾기 | 100 | 2시간마다 12회 → **1,200** |
| 합 | | **~8,900** |

★ **`BC_YT_MAX`(60)나 주기를 늘리면 이 합을 다시 셀 것.** 로컬 서버도 같은 키라 같이 먹는다(요청할 때만).
재부팅(배포)마다 검색이 다시 돌지 않게, 마지막 검색 시각을 `ytchannels.searchAt` 최댓값에서 잇는다.

#### 명단 규칙

- **자동 명단(`ytchannels`)** — 새 채널 찾기에서 **한글 제목 + 롤 신호 + 다른 게임 이름 없음**인 방송의 채널이 들어간다.
  방송이 잡힐 때마다 `lastLive` 가 갱신되고, **14일 동안 안 잡히면 확인 대상에서 빠진다**(문서는 남는다).
  확인 대상은 `lastLive` 최신 순 60개
- **손 명단(`broadcast_channels.js`)** — `include` 는 항상 확인, `exclude` 는 절대 안 보임. 값은 채널 ID(`UC…`)

**★★ 롤 신호를 뺐더니 망가졌다 (실측).** 처음엔 「검색어가 `롤` 이니 제목 조건은 필요 없다」고 봤는데,
게임 카테고리 전체가 딸려 와서 **38채널 중 절반이 리니지·디아2·림버스**였다. 그래서 신호를 되살렸다 —
- `BC_LOL_RE` — 롤 · 리그 오브 레전드 · lol · lck · 솔랭 · 자랭 · 칼바람 · 협곡 · 원딜 · 서폿 · 챌린저 · 그마 · ○딱 · 칼챔 …
- 챔피언 한글 이름 — `champKeyMap`(부팅 때 받는 `champion.json`)에서 **세 글자 이상만**.
  두 글자는 흔한 낱말(아리·진·세트·조이·유미·애니)이라 헷갈릴 일 없는 것만 `BC_CHAMP_2` 에 따로 둔다
- 대가: 롤 방송인이라도 그날 제목에 신호가 없으면(큰코3 「취두부미션」) 그날은 못 잡는다. 다른 날 제목으로 잡힌다

**다른 게임 거르기(`BC_OTHER_GAME_RE`)** — 명단 채널이 다른 게임을 켜도 API 로는 알 수 없어서 **제목에 다른 게임 이름이 있으면 뺀다** (사용자 결정).
명단 확인 때도 같은 규칙을 쓴다. 제목에 게임 이름이 없는 다른 게임 방송은 그대로 보인다 — 그게 이 방식의 한계다.
- ★ 짧은 줄임말(발로·로아·마크)은 넣지 않았다 — 다른 낱말 안에 흔히 들어 있다
- 뒷줄(리니지·아이온·림버스·팰월드·DK온라인·열혈강호·에오스·디아2/4·래더·닌텐도·역전재판·lofi·이클립스 …)은
  실측에서 실제로 딸려 온 것들이다. **새로 섞이는 게임이 보이면 여기에 더하거나 채널을 `exclude` 에 넣는다**

## 화면

- 칩: 전체 / SOOP / 치지직 / 유튜브 (옆에 개수). **주소는 안 바꾼다** — `/broadcast` 하나라 라우터 두 곳은 원래 있던 한 줄 그대로다
- 카드: 16:9 썸네일 + 왼쪽 위 플랫폼 배지 + 오른쪽 위 시청자 수 + 프로필·제목(두 줄)·방송인·방송 시간
- 60개씩, 「더 보기」
- 페이지에 머무는 동안 90초마다 다시 받는다 (다른 화면으로 가면 멈춘다)
- 폰(≤768)은 2열
- 실측: 1400 / 820 / 390 넘침 0 · 유튜브 칩 → 11장 전부 유튜브 · 주소 그대로
- ★ **헤드리스 `--window-size=390` 스크린샷은 믿지 말 것** — 새 헤드리스는 창 폭 하한이 있어 390 보다 넓게 그려 놓고 잘라서 **가로로 넘친 것처럼 보인다.**
  CDP `Emulation.setDeviceMetricsOverride` 로 재야 한다 (반복 함정 14번과 같은 부류)

## 남은 것

- SOOP `total_view_cnt` 가 정말 현재 시청자인지 저녁에 화면과 대조
- 유튜브 명단이 쌓인 뒤(며칠) 헛것이 섞였는지 보고 `exclude` 정리
- 할당량이 모자라면 구글에 증액 신청 (무료, 심사)
