## CD 스킬 데이터 작업 (현재 주 작업)

### 구조

- `public/custom_templates.js` = 문장, `public/custom_values.js` = 수치. `index.html`이 직접 로드
- 문장 안 빈칸은 `{p1}` `{p2}` 형식
- `v1`·`v2`는 구분선 아래 피해량 줄 (p랑 역할이 다름). 지금 전부 비어 있고 직접 작성 대상
- `stats`는 객체 형식 `{ "사거리": "300" }`

**★ 언제 돌려야 하나 — DD 와 CD 는 약 12시간 차이가 난다 (2026-08-13 실측).**

| 소스 | 갱신 시각 |
|---|---|
| **DD** (`championFull.json`) | 매 패치 **화요일 19:0x UTC** = **수요일 04:0x KST** |
| **CD** (`latest` 경로 전부) | 그로부터 **약 12시간 뒤** = **수요일 16:0x KST** |

DD 는 시계처럼 규칙적이다 — 16.13.1 부터 16.16.1 까지 넷 다 화요일 19:06~19:13 UTC 였다.
CD 는 16.16 실측이 `bin 06:58 / stringtable 07:08 / champion-summary 07:13 UTC` 였다.

- **패치 당일에는 한국시간 오후 4시 이후에 돌릴 것.** 그 전에 돌리면 **DD 는 새것, CD 는
  헌것**이라 값 이름이 어긋나고 `?` 가 무더기로 생긴다 (2026-08-12에 실제로 겪었다)
- 돌리기 전 확인:
  `curl -sI https://raw.communitydragon.org/latest/plugins/rcp-be-lol-game-data/global/ko_kr/v1/champion-summary.json | grep -i last-modified`
  날짜가 패치 당일이면 반영된 것이다
- **CD 의 버전별 경로(`/16.15/`, `/16.14/`)의 Last-Modified 는 믿지 말 것.**
  16.13 과 16.14 가 `6/26 22:37` 로 **같은 시각**이다 — 아카이브되면서 일괄 갱신된 값이라
  "그 버전이 처음 올라온 시각" 이 아니다. 진짜 반영 시각은 `latest` 경로에만 남는다

**★ 패치를 받은 뒤 반드시 확인할 것 — "값이 통째로 평평해진 스탯" (2026-08-12 사고).**
16.16 에서 **173명 전원의 마법 저항력 성장이 0** 이 됐다. 화면에는 수평선으로 조용히
나가서 눈으로는 안 걸린다. 원인은 **패치가 아니라 우리 코드**였다:

- `build_level_curves.js` 의 `mf()` 가 **키를 하나만** 봤고, 호출부가 `mf(root, hk('mrPerLevel'))`
  처럼 **해시를 직접 만들어** 넘기고 있었다
- **CD 는 이번 패치부터 이 필드를 실명(`mrPerLevel`)으로 풀어 준다.** 해시 키가 사라지니
  빈손이 됐고, 기본값(`baseMR`)은 실명이라 살아남아 **"기본값만 있고 성장은 0"** 이 됐다
- `mf()` 를 `fld()` 기반으로 바꿔 **해시·실명 둘 다** 보게 했고 호출부의 `hk()` 를 벗겼다.
  자원(`arBase`/`arPerLevel`/`arBaseStaticRegen`/`arRegenPerLevel`) 4자리도 같은 지뢰였다
- **검산법**: `champion_stats_by_level.json` 에서 스탯별로 "18칸이 전부 같은 값인 챔피언 수"를
  세어 이전 판과 비교한다. 갑자기 173/173 이 되면 그 스탯이 죽은 것이다.
  **압축본(`champion_stats.js`)은 4줄만 바뀌어서 diff 로는 안 보인다** — 원본 json 을 볼 것
- 이 버그에 가려 **원거리 딜러 28명의 진짜 MR 상향(30 → 33)** 이 안 보이고 있었다

**`DD_VER` 하드코딩은 2026-08-24에 없앴다** — `dd_version.js` 가 `versions.json` 의 최신을 받아 온다.
패치 때 손으로 올릴 자리는 이제 없다 (아래 25번 절).

**★★ 오류가 숨는 구조는 하나다 — "값을 못 읽으면 조용히 0 이 된다" (2026-08-12).**
같은 날 나온 세 건이 전부 이 모양이었다:

| 오류 | 표면 증상 |
|---|---|
| `mrPerLevel` 을 해시 키로만 조회 | 173명 마법 저항력 성장 0 (수평선) |

셋 다 **예외로 안 터지고 그럴듯한 숫자로 화면에 나가서** 눈으로 안 걸렸다.

**더 뼈아픈 건 교차검증 코드가 이미 있었는데 못 잡았다는 것이다.**
`mrPerLevel` 은 `CHECK` 목록에 **있었는데** 당시 bin 이 해시 키라 `undefined` 가 되고,
`if (bv === undefined) continue` 에서 조용히 빠졌다 — **검사 대상인데 검사가 안 됐다.**

그래서 고쳤다: **① `mf()` 로 조회(해시·실명 둘 다) ② 못 읽은 필드를 건너뛰지 말고
경고로 출력 ③ `CHECK` 에 체력 재생 추가.** 지금 파이프라인이 이렇게 찍는다:

```
★ bin 에서 못 읽은 필드 4종 — 0 으로 나가면 사고다. DD 값을 확인할 것:
  baseStaticHPRegenModifiable  8명   Kayle, Maokai, ...
```

**이 줄이 늘어나면 반드시 DD 와 대조할 것.** 지금 4종은 전부 정당하다 —
세나 공격력·쓰레쉬 방어력은 영혼으로 크고(DD 도 0), 브라이어는 체젠이 없다.
**"필드 없음 = 0" 이 아니라 "= 라이엇 기본값" 일 수 있다는 게 핵심이다.**

**`bincache.js` — 재실행이 166초에서 9초가 된다 (2026-08-10 추가).**
두 생성 스크립트가 챔피언 173명 bin 을 매번 새로 받던 걸 `.cache/bin/` 에 7일 캐시한다.
표 한 줄 고치고 결과를 보는 짧은 반복이 이것 때문에 통째로 느렸다.
캐시로 만든 결과가 **기존 파일과 바이트 단위로 동일**한 것까지 확인했다.

- **패치 직후에는 `--refresh` 를 붙일 것.** 안 그러면 최대 7일 묵은 bin 을 본다
- 캐시 적중이면 챔피언 사이 대기시간(120~150ms)도 건너뛴다 — 그게 20~26초였다
- 받기에 실패하면 오래된 캐시라도 쓴다 (CD 가 잠깐 죽어도 작업이 안 멈춤)
- `.cache/` 는 gitignore 대상. 지워도 다시 받으면 그만이다

`fill_values.js` 안의 표 두 개가 중요해:

- **`MANUAL`** — `"미스 포츈 W / LoveTapRefund"` 형식 키. 손으로 확인한 값을 적으면 자동 추출보다 우선하고 재실행해도 안 날아감. 영문 alias도 허용. 안 쓰인 키는 오타 경고로 잡힘. 현재 9건
- **`PRESERVE`** — **2026-08-08에 비웠다(`[]`).** 가렌·갈리오가 유일한 항목이었는데 `{pN}` 체계 이전의 옛 형식(pN이 아예 없음)이라 구조가 달랐어. 이제 전부 CD에서 받아옴
- **`extractVV()`** — 손으로 쓴 `v1`/`v2`를 기존 파일에서 **원문 그대로** 물려줘. 여러 줄짜리(`drawGraph` 호출 등)도 줄 단위로 옮기니까 안 깨져. **PRESERVE 없이도 손작업이 안 날아가는 이유가 이거야.** 지금은 `v1`/`v2`가 전부 비어 있어서 아무것도 안 물려주지만, 앞으로 작성할 때를 위해 남겨둔 장치야

`--write`는 `public/custom_values.new.js`를 만들어. 확인한 뒤에 `custom_values.js`로 이름을 바꿔야 반영돼.

### 스킬 칸 우상단 값 전수조사 — `audit_skill_meta.js` (2026-08-14 신설)

화면 우상단에 나가는 건 네 종류다 (`app.js` 의 `champ-skill-cooldown-header` ·
`champ-skill-cost-header` · `champ-skill-stats-header`):
**쿨타임 / 소모값 / `stats` 전체(사거리 · 시전시간 · 투사체 속도 · 스킬 폭)**.

```
node audit_skill_meta.js           # 지금 화면에 나가는 custom_values.js 를 본다
node audit_skill_meta.js --new     # fill_values.js 가 갓 만든 .new.js 를 본다
node audit_skill_meta.js --full    # 예시를 안 자르고 전부 찍는다
```

**★ 대조 상대가 셋이라 교차검증이 된다** — 우리 값 / **DD `championFull`**(독립 출처,
`cooldownBurn`·`costBurn`·`rangeBurn`·`maxrank`) / **bin**(원본. 값이 **어느 스펠 객체에서
왔는지**까지 본다). 14가지를 센다: 패시브 쿨 누락, 쿨타임·소모값·사거리의 DD 불일치,
칸 수 불일치, 빈칸, 투사체 속도 오염 등.

- **★ 첫 실행에서 410자리가 걸렸고 지금은 2자리다.** 고친 것 —
  패시브 쿨타임 20 + 사거리 밀림 17 + 투사체 속도 오염 310 + 사거리 더미 37.
  **남은 2자리는 둘 다 정당하다** — 암베사 P(라이엇이 stringtable 문장을 비워 뒀다) /
  잔나 W(우리 `550` 이 DD 의 `4294967295` 보다 낫다)
- **★★ 쿨타임과 소모값은 DD 와 100% 일치한다.** 865슬롯 전수에서 불일치 0,
  칸 수 불일치 0, 빈칸 0. **`MAX_RANK` 표(우디르 6랭크 등)도 이걸로 검증된다** —
  칸 수가 DD `maxrank` 와 어긋나면 ③번에 걸린다
- **★ "값이 있다" 와 "값이 맞다" 는 다르다.** 투사체 속도는 634자리가 **꽉 차 있어서**
  겉보기엔 완벽했는데 절반이 남의 값이었다. **빈칸을 세는 것만으로는 못 잡는다** —
  값의 **출처**를 bin 에서 되짚어야 드러난다

**★★★ 라이엇 데이터끼리만 대조하면 "일관되게 쓸모없는 값" 은 절대 안 걸린다 (2026-08-14).**
DD 와 bin 은 **같은 라이엇 소스**라, 둘이 일치한다는 건 "라이엇이 그렇게 적었다" 는 뜻이지
**"그게 화면에 나갈 값이다" 는 뜻이 아니다.** 사거리 `25000` 이 정확히 이 함정이었다 —
DD `rangeBurn` 도 25000, bin `castRange` 도 25000 이라 **기계 대조에서 불일치 0** 이 나왔고,
그래서 나는 이걸 **정당한 값으로 한참 착각했다.** 깨준 건 "아트록스 Q·유미 Q 는 전역이
아닌데?" 라는 지적이었고, 확인해 보니 롤위키는 유미 W 를 **700**, 아트록스 Q 를
**`RANGE: Varied`** 라고 적고 있었다.

|---|---|---|
| **DD `championFull`** | 대량 기계 대조 (865슬롯 즉시). 쿨타임·소모값이 여기서 100% 검증됐다 | bin 과 같은 소스라 **둘 다 틀린 값**은 못 잡는다 |

- **★★ 위키에서 우상단 값을 찾는 법 (2026-08-14 실전 정리).**
  - **롤위키 스킬 상자에 `SPEED:` 가 있다** — 투사체 속도를 여기서 얻는다.

### 폴백을 푸는 두 번째 방법 — "문장에서 빼기" (2026-08-09)

빈칸이 **"지금 내 챔피언의 현재 수치"** 라서 고정값이 아예 없는 자리가 있다
(카이사 진화 게이지, 스몰더 현재 중첩, 바드 현재 성소 수 등).
**MANUAL 로 숫자를 넣으면 거짓말이 된다.** 문장에서 빼는 게 맞다.

**단, 문장에서 `{pN}` 을 지우는 것만으로는 폴백이 안 풀렸다.** 두 가지를 알아야 한다.

1. **값 쪽 `pN` 은 지워도 소용없다.** `fill_values.js` 는 문장이 아니라 **CD 원본 `desc` 의
   `@Name@` 을 훑어서** p1..pN 을 만든다. 손으로 지워도 재실행하면 되살아난다
2. **그래서 `app.js` 의 가드를 고쳤다.** 예전엔 `values` 의 **모든** `pN` 을 검사해서,
   문장이 안 쓰는 자리의 `?` 까지 세고 멀쩡한 문장을 통째로 버렸다.
   지금은 **문장에 실제로 등장하는 `{pN}` 만** 본다 (`tpl.includes('{'+k+'}')`).
   가드의 목적이 "화면에 물음표가 찍히는 걸 막는 것" 이니 이게 맞다

이 방식은 **템플릿만 고치면 되고 `fill_values.js` 재실행에도 안전하다.**
8스킬이 이렇게 풀렸다.
